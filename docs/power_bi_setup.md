# Power BI Desktop setup

The Python project prepares the data. Build and validate the visual report in Power BI Desktop. This starter package does not contain a finished `.pbix` file.

## 1. Generate the data files

From the project root, run:

```powershell
python -m climate_dashboard.pipeline
python -m climate_dashboard.adversarial
```

## 2. Import data

In Power BI Desktop:
1. Choose **Get data → Text/CSV**.
2. Import `data/processed/trusted_data.csv`.
3. Rename the table to `TrustedData`.
4. Import `data/processed/adversarial_data.csv` and rename it to `AdversarialData`.
5. Import `data/processed/adversarial_change_log.csv` and rename it to `ChangeLog`.
6. Import `data/processed/validation_report.json` if desired for a simple validation summary. Alternatively, display the generated report separately in the project documentation.

## 3. Set data types

- `value`: Decimal number
- `data_year`: Whole number
- All identifiers, metric names, units, source fields, statuses, and descriptions: Text

## 4. Page 1 — Environmental Overview

Suggested visuals:
- **Slicer:** `TrustedData[metric]`
- **Slicer:** `TrustedData[data_year]`
- **Slicer:** `TrustedData[company]`
- **Clustered bar chart:** Axis = `TrustedData[company]`; Values = `TrustedData[value]`; visual filter = one selected metric
- **Cards:** selected metric, selected year, record count
- **Table:** company, facility, metric, value, unit, source name, data year, lifecycle boundary, data status, limitation

Important:
- Do not sum different metrics together. Use a metric slicer or separate chart per metric.
- Do not compare raw totals across companies unless the reporting boundaries and periods are compatible.
- Add the unit to chart titles or labels.
- Keep `synthetic_demo` visible as a status until the sample data is replaced.

A native Power BI chart responds to slicers and filters without requiring Python-generated chart images.

## 5. Page 2 — Data Integrity

Suggested visuals:
- Table showing record IDs, metric, source, data status, and limitations.
- Card showing the validation status from `validation_report.json`.
- Text or card with the SHA-256 from `trusted_manifest.json`.
- A note explaining that the manifest must be protected independently from the data.

The manifest is generated by Python; Power BI does not independently authenticate it just because it displays the hash. Verification is performed by `python -m climate_dashboard.integrity ...`.

## 6. Page 3 — Adversarial Comparison

Suggested visuals:
- Two side-by-side bar charts: trusted values vs adversarial values for the same metric.
- A table sourced from `ChangeLog` showing each manipulation and detection evidence.
- A card or text indicator showing the expected result of a trusted-hash verification.
- A note that the adversarial dataset is an intentional simulation.

Because the water rows are removed from the adversarial dataset, a comparison should make the missing category visible rather than silently treating it as zero. If you build relationships between trusted and adversarial records, use `record_id` only when the record exists in both versions; use a separate record/metric dimension if you need to show missing records explicitly.

## 7. Refresh workflow

After replacing or editing raw input data:
1. Run `python -m climate_dashboard.pipeline`.
2. Review `data/processed/validation_report.json`.
3. Verify the trusted file against its manifest.
4. Regenerate the adversarial copy.
5. Refresh the Power BI model.
6. Recheck source metadata, units, and chart filters.

## 8. Save and submit

Save the report in Power BI Desktop. Keep the `.pbip` project and related source files in version control if you use project format. Follow the instructor's submission instructions for whether a `.pbix`, screenshots, source code, or all project files are required.
